# 喝水记录 App 架构文档

> 一句话描述：一个不联网、不登录、数据只存在手机本地的每日喝水记录 App。

---

## 1. 项目概述

| 项目 | 内容 |
|---|---|
| App 名称 | 喝水记录 |
| 平台 | Android（单平台） |
| 最低系统 | Android 8.0（API 26） |
| 目标系统 | Android 16（API 36） |
| 语言 | Kotlin |
| UI 框架 | Jetpack Compose + Material 3 |
| 数据存储 | Room（本地 SQLite 数据库文件） |
| 网络 | **完全无网络**（不申请任何网络权限） |
| 账号 | **无登录**，无任何账号体系 |

### 功能范围（本期）

1. **今日记录**：点击常用容量按钮（150 / 250 / 500 ml）一键记录，或输入自定义容量；显示今日总饮水量；今日记录列表可删除单条。
2. **历史统计**：近 7 天 / 近 30 天每日饮水总量柱状图，以及平均值、最高单日等汇总数字。

### 明确不做（本期）

- 不做每日目标 / 进度圆环
- 不做喝水提醒通知
- 不做云端同步、导出、账号

## 2. 技术选型及理由

| 选项 | 选择 | 理由 |
|---|---|---|
| 开发语言 | Kotlin | Android 官方语言，长期维护有保障 |
| UI | Jetpack Compose | Android 官方现代 UI 框架，写界面代码量少 |
| 数据库 | Room | 官方本地数据库，数据落在手机私有目录的一个文件里，重启不丢 |
| 架构模式 | MVVM + Repository | 官方推荐的分层写法，界面与数据解耦，后续好维护 |
| 异步 | Kotlin Coroutines + Flow | 官方推荐，数据变化自动刷新界面 |
| 图表 | Compose Canvas 自绘柱状图 | 需求只是简单柱状图，自己画 100 行以内代码，避免引入第三方图表库（减少依赖、减小体积） |
| 依赖注入 | 手动注入（Application 容器） | App 很小，不引入 Hilt 等 DI 框架，构建更简单不易出错 |
| 页面切换 | Compose 状态切换（底部两页签） | 只有两个页面，不引入导航库 |

> 版本管理：所有第三方依赖统一记录在 `gradle/libs.versions.toml`（版本目录），具体版本号以 Android Studio 项目模板生成的最新稳定版为准，不在本文档中硬编码。

## 3. 总体架构

单 Activity + Compose，经典三层结构：

```
┌─────────────────────────────────────────────┐
│  UI 层（Compose）                             │
│  TodayScreen / StatsScreen + ViewModel       │
│  （界面展示 + 用户交互）                       │
├─────────────────────────────────────────────┤
│  数据层（Repository）                         │
│  DrinkRepository                             │
│  （对上暴露 Flow 数据流，对下调用数据库）        │
├─────────────────────────────────────────────┤
│  存储层（Room / SQLite）                      │
│  AppDatabase + DrinkRecordDao                │
│  （真正读写手机本地数据库文件）                 │
└─────────────────────────────────────────────┘
```

**数据流向（单向）**：数据库 → Repository（Flow）→ ViewModel（StateFlow）→ 界面自动刷新。
用户点击按钮 → ViewModel → Repository → 数据库写入 → Flow 自动把新数据推回界面。

**隐私保障**：`AndroidManifest.xml` 中不声明 `INTERNET` 等任何网络权限，同时设置 `android:allowBackup="false"`。这意味着：

- App 在技术上**不可能**联网（系统层面直接禁止）
- 数据不会被系统备份到云端，真正做到只存本机

交互说明：

- 点常用按钮：立即写入一条记录，无需确认，按钮区域显示短暂成功反馈

- 列表按时间倒序；点"删除"移除该条（带 Snackbar 撤销，防误删）
- 跨天后自动进入新的一天，列表清空重来，历史进入统计页

## 5. 数据模型与存储

### 5.1 表结构（仅一张表）

`drink_records` 饮水记录表：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | 主键，自增 |
| amount_ml | Int | 饮水量，毫升 |
| created_at | Long | 记录时间，毫秒时间戳 |

> 不单独建"每日汇总表"——总量用 SQL `SUM` 现算即可，数据量极小（一天几十条），无需冗余。

### 5.2 DAO 主要查询

- `insert(record)`：插入一条
- `deleteById(id)`：按 id 删除
- `observeAll(): Flow<List<DrinkRecord>>`：监听全量记录，界面订阅后数据一变就自动刷新
- 按天分组、区间求和等统计逻辑在 Kotlin 层完成（`LocalDate` 分组），SQL 只做最简单的存取，便于测试

### 5.3 数据存放位置与安全性

- 数据库文件位于 **App 私有目录**（`/data/data/<包名>/databases/`），Android 系统禁止其他 App 读取
- 无需申请任何存储权限
- 卸载 App 即删除全部数据（本地存储的正常行为，会在文档与 App 内说明）

## 7. 关键技术决策记录

| # | 决策 | 原因 |
|---|---|---|
| 1 | minSdk 26 | Android 8.0 覆盖绝大多数在用手机；且 26 起 `java.time` 日期 API 原生可用，按天分组统计不用额外兼容库 |
| 2 | 不声明任何权限 | App 功能完全不需要权限；无 `INTERNET` 权限 = 物理上无法联网，是对"不联网"承诺的最强保证 |
| 3 | `allowBackup=false` | 默认系统会把 App 数据备份到用户 Google 账号（走网络），关掉以确保数据不离开手机 |
| 4 | 单 Activity | Compose 官方推荐，全部页面在 Activity 内切换，减少模板代码 |
| 5 | 图表自绘 | 需求仅为柱状图，自绘零依赖、体积小；若未来需要复杂图表再引入 Vico 等库 |
| 6 | 手动依赖注入 | 两个 ViewModel + 一个数据库，手动传递依赖足够，避免 DI 框架带来的构建复杂度 |
| 7 | 界面文案中文、代码注释最小化 | 目标用户为个人自用 |

## 8. 一次完整的数据流示例

以"用户点击 +250ml 按钮"为例：

```
1. TodayScreen 中按钮 onClick
2. → TodayViewModel.addWater(250)
3. → viewModelScope 协程中调用 DrinkRepository.addRecord(250, 当前时间)
4. → Room 写入 SQLite 文件（app 私有目录）
5. → Room 的 Invalidator 检测到表数据变化
6. → observeAll() 的 Flow 发射新数据列表
7. → ViewModel 把列表转换成 UiState（今日总量 + 按天过滤后的今日列表）
8. → Compose 界面自动重组刷新：总量数字、列表都更新
```

全程无需手动刷新界面，也无需回调。

## 9. 构建与测试

- **开发工具**：Android Studio（最新稳定版），用其自带 JDK/SDK 管理器，无需手动配置环境
- **运行方式**：USB 连接真机（开启开发者模式）或使用 Android Studio 模拟器
- **单元测试**：对"按天分组统计、今日过滤、平均值计算"等纯逻辑写 JUnit 测试（`app/src/test/`）
- **出安装包**：Android Studio 菜单 Build → Build APK，产出 `app-debug.apk` 直接发到手机安装；如需长期自用可再生成带签名的 release 包
